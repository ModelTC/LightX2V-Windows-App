# v0.3.12 · Recovery, first-use guidance, and maintainability

## Recovery and model repair

Damaged preferences and history indexes are preserved before recovery. Preferences can be restored from the last valid backup, and history can be rebuilt from saved task records. A valid but stale index reconciles newer task records without restoring older creations deliberately removed from history. Unsupported newer workspace formats are rejected before changing the current configuration.

Legacy workspace detection now falls back to fresh setup with a diagnostic when its baseline configuration cannot be read. Startup failures are handled around initialization so that an error cannot silently leave a windowless app holding the single-instance lock.

Stopping generation still reaches bounded process termination if the cancellation signal cannot be written. Ordinary JSON dependency logs are kept as logs; only validated, versioned backend events reach the generation handlers. Failed stream callbacks stop the child and peer reader, and terminal cleanup restores UI ownership even when saving a task record fails.

Downloads can switch sources after a failed range without waiting for other slow, dripping connections to finish. Early EOF preserves resumable bytes; complete files with incorrect checksums are still rejected. Cancelled or failed transfers finish their file-writing workers before returning.

Model readiness now checks required configuration, tokenizer, processor, scheduler, sampling values, and checkpoint structure. Model cards and download guides offer **Check and repair**, including for a model already marked ready. This explicitly verifies source hashes and fetches missing or damaged files. Ordinary startup does not hash all model weights.

## First-use guidance

Environment discovery prioritizes the selected and managed Python executables and publishes usable candidates while other checks continue. Users can select and prepare a candidate immediately. Background discovery has a 45-second overall budget, and a verified candidate can be reused within the session after checking its backend and executable fingerprint.

The composer explains why generation is unavailable. Missing prompt enhancement offers the download appropriate to text-to-image or reference-image editing, together with **Use the base model**. Optional enhancement downloads can continue while basic generation remains available. The sidebar uses workflow names for the two enhancement models.

## Shared configuration and validation

C# and Python now share a versioned model catalog containing repositories, required files, and supported layouts. The catalog documents its compatible Hugging Face `main` / ModelScope `master` policy; it does not claim immutable model revisions. Packaging verifies that the catalog and other root JSON resources match the committed source.

Persistence, backend protocol parsing, generation events and cleanup, guidance, and model-download guides have clearer code boundaries. CI executes offscreen core checks and adds a separate pinned CPU PyTorch job whose selected tests must pass without skips. Publication waits for both jobs.

## Validation scope

- All four C# projects compiled with zero warnings and zero errors.
- The Windows Python suite ran 160 tests: 151 passed and nine opt-in hardware/model checks were skipped.
- All 38 selected CPU tensor/checkpoint tests passed without skips. The development runtime did not initialize the GPU during this CPU-only run.
- Offscreen core validation passed 246 assertions covering startup, readiness, recovery, protocol handling, model repair, download state, and first-use guidance.
- Full offscreen/native AMD validation passed 417 assertions. Real model-download cancellation and missing-file recovery reused verified GGUF weights and fetched the missing small files.
- An actual AMD 512×512 text-to-image task, with enhancement disabled, completed all eight steps and produced a valid PNG in 34.13 seconds through the app's generation flow.

Assertion counts include layout checks and are not counts of independent user scenarios. Fixture screenshots are distinct from the real generated image. RTX hardware validation for this release remains open; earlier results retain their documented version and hardware scope.

## Upgrade and RTX validation

Close the old app, extract the complete ZIP into a new program folder, and select the existing workspace. Installed environments and complete model files can be reused.

On RTX, first generate a 512 / 1:1 image with enhancement disabled. Then check stop/retry, reopening the workspace, an optional enhancement download while using the base model, and **Check and repair**. After these pass, validate 1K, 2K, reference-image editing, and prompt enhancement. Preserve task logs when reporting a failure; review personal paths, prompts, and reference images before sharing them.
