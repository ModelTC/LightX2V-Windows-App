# v0.3.7 · Automatic resource planning and runtime diagnostics

## Select a resource strategy automatically before generation

AMD ROCm and NVIDIA CUDA share planning logic based on model metadata and currently available resources. The app accounts for the DiT, text encoder, and VAE separately, and distinguishes discrete GPUs from shared-memory devices.

When capacity is sufficient, the app retains the normal inference path with full model residency. When resources are limited, it uses component offloading, block offloading, or BF16 disk streaming as needed. The text encoder can read layers on demand and look up vocabulary entries on the CPU, avoiding simultaneous loading of the entire encoder onto the GPU. The single-request worker releases the encoder as soon as text encoding finishes, while the DiT can remain resident on the GPU. The VAE selects tiled decoding according to its budget.

Prompt enhancement selects the number of GPU layers from GGUF metadata and available resources; remaining layers run on the CPU. Resources are checked again after the enhancement process exits and releases its resources, before starting the image model.

## Preserve the interface and creation settings

This release adds no performance modes or manual offloading options. Initial setup, model preparation, dimensions and aspect ratio, reference-image editing, the prompt-enhancement toggle, history, and stopping tasks retain their existing workflows.

Models continue to use BF16. Qwen-Image-2.1-Turbo retains its fixed 8 steps and associated sampling parameters. Resource planning does not automatically reduce the selected output dimensions or disable enhancement. Smaller dimensions reduce only part of the image working memory and are not a general solution to insufficient memory during model loading.

## Resource diagnostics

Task directories now include automatic resource plans and runtime telemetry:

- `resource-plan.json` records weight statistics, resource budgets, the selected path, and the reasons for that choice.
- `telemetry.jsonl` and `resource-usage.json` record stages within the worker and GPU allocator / host-memory metrics.
- `host-telemetry.jsonl` and `host-resource-usage.json` retain host samples and protection events for the task's child processes.

Runtime protection responds to sustained severe memory pressure, so brief loading fluctuations do not trigger termination based on a fixed large memory margin. Records already written are retained after failure or cancellation. Windows commit is measured through the system API; pagefile-based proxies are explicitly labeled and are not presented as exact commit measurements.

See [Automatic resource planning](../automatic-resources.md) for strategy details, field definitions, and manual RTX acceptance steps.

## Validation scope

The following checks were completed on Radeon 8060S in a native Windows 11 environment:

- Automatically selected resident path: 512 and 1K text-to-image generation, plus 512 reference-image editing.
- With constrained resource budgets supplied by the test program: BF16 disk streaming for both components, covering 512 and 1K text-to-image generation and 512 reference-image editing.
- Prompt enhancement with partial GPU offloading, followed by streaming 512 generation.
- Streaming and resident outputs for the first two DiT and text-encoder layers from the official checkpoint were exactly equal element by element.
- Resident and streaming 512 text-to-image PNGs were byte-identical. For 1K output, tiled VAE decoding produced approximately 60.24 dB RGB PSNR against the untiled image.
- After promptly releasing the single-request encoder, one resident 1K pipeline sample took approximately 95.58 seconds and the corresponding streaming sample approximately 145.98 seconds, excluding model loading.
- Peak PyTorch allocations in streaming samples were approximately 2.57 GiB for 512 text-to-image, 3.63 GiB for 512 editing, and 6.36 GiB for 1K text-to-image.
- All 96 Python checks passed, including numerical comparisons of real GPU layers and Windows DXGI API checks. An additional 30 offscreen startup UI checks passed.
- A dedicated 2048×2048 tiled VAE decoding check passed, with correct output dimensions and finite values. This does not constitute full 2K text-to-image acceptance testing.

These results cover actual execution and budget-controlled branches on the AMD development machine. They do not certify capacity on a machine with an 8 GB discrete GPU or 32 GB of physical RAM. Full 2K text-to-image generation was not rerun for this release; that size still requires validation on the actual device.

**NVIDIA CUDA had not completed RTX hardware acceptance testing for this release.** RTX 4070 Laptop 8 GB + 32 GB RAM remained a manual acceptance target. This release does not claim general support for 8 GB VRAM, or treat unit tests, successful compilation, or a passed environment check as proof of successful image generation.

To upgrade, close the old app, extract the entire new version into a new folder, and continue using the existing working directory. Complete models and prepared environments can be reused, but the runtime environment must still pass its check.
