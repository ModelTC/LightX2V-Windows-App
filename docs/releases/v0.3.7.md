# v0.3.7 · 自动资源规划与运行诊断

## 生成前自动选择资源策略

AMD ROCm 与 NVIDIA CUDA 共用按模型元数据和当前资源规划的逻辑。程序分别统计 DiT、文本编码器和 VAE，并区分独立显卡与共享内存设备。

容量充足时保留完整驻留的普通推理路径；受限时按需使用组件卸载、block 卸载或 BF16 磁盘流式。文本编码器可逐层读取并在 CPU 查询词表，避免把完整编码器同时载入 GPU。单请求 worker 在文本编码结束后立即释放不再使用的编码器，DiT 仍可保持 GPU 常驻。VAE 按预算选择分块解码。

Prompt 增强根据 GGUF 元数据与可用资源选择 GPU 层数，其余层由 CPU 处理。增强进程释放后重新检查资源，再启动图像模型。

## 保留现有界面与创作设置

本版不增加性能模式或手动卸载选项。首次向导、模型准备、尺寸与比例、参考图编辑、Prompt 增强开关、历史记录及停止操作保留现有流程。

模型继续使用 BF16；Qwen-Image-2.1-Turbo 保留固定 8 步及配套采样参数。资源策略不自动降低用户选择的输出尺寸，也不替用户关闭增强。较小尺寸只减少部分图像工作区开销，不能作为模型加载内存不足的通用解决方法。

## 资源诊断

任务目录新增自动资源计划和运行遥测：

- `resource-plan.json` 记录权重统计、资源预算、所选路径及原因。
- `telemetry.jsonl`、`resource-usage.json` 记录 worker 内部阶段与 GPU allocator/主机内存指标。
- `host-telemetry.jsonl`、`host-resource-usage.json` 保存所属子进程的主机采样与保护事件。

运行中使用持续严重内存压力判定，避免短暂加载波动触发固定大余量终止。失败或停止时保留已写入记录。Windows commit 使用系统 API；pagefile 代理会明确标注，不冒充精确 commit。

具体策略、字段解释和 RTX 手工验收步骤见 [自动资源规划](../automatic-resources.md)。

## 验证范围

本版在 Radeon 8060S / Windows 11 原生环境完成以下验证：

- 自动选择的驻留路径：512、1K 文生图和 512 参考图编辑。
- 测试程序提供受限资源预算时：BF16 双组件磁盘流式的 512、1K 文生图及 512 参考图编辑。
- 部分 GPU 提示词增强与 512 流式生成串联。
- 官方 checkpoint 前两层 DiT 和文本编码器的流式/驻留输出逐元素完全一致。
- 512 文生图的驻留/流式 PNG 字节完全一致；1K 使用 VAE 分块时与未分块图像的 RGB PSNR 约 60.24 dB。
- 单请求编码器及时释放后，1K 驻留 pipeline 样本约 95.58 秒；对应流式样本约 145.98 秒，均不含模型加载。
- 流式样本的 PyTorch 峰值分配：512 文生图约 2.57 GiB，512 编辑约 3.63 GiB，1K 文生图约 6.36 GiB。
- 96 项 Python 检查全部通过，包含真实 GPU 层数值对照与 Windows DXGI API 检查；另有 30 项界面启动离屏检查通过。
- 2048×2048 VAE 分块解码专项通过，输出尺寸和有限值检查正常；这不等于完整 2K 文生图验收。

这些是 AMD 开发机上的实际执行与预算分支验证，不是 8 GB 独显或 32 GB 物理内存机器的容量认证。本版没有重新执行完整 2K 文生图；该尺寸仍需要按实际设备验收。

**NVIDIA CUDA 尚未完成本版 RTX 实机验收。** RTX 4070 Laptop 8 GB + 32 GB 内存仍为手工验收目标；本版不宣称 8 GB 显存已普遍支持，不把单元测试、编译成功或环境检查通过当作生成成功的证明。

升级时关闭旧 App，完整解压新版到新文件夹，继续使用原有工作目录。完整模型及已准备环境可复用，仍需通过运行环境检查。
