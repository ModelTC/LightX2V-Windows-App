# v0.3.10 · Automatic download sources and a shorter first-time setup

The v0.3.10 tag stopped during CI test validation. Use the v0.3.11 internal beta for the downloadable release. See [v0.3.11 release notes](v0.3.11.md).

## Automatic download source selection

New installations default to **Automatic (recommended)** for model downloads. The app probes Hugging Face and ModelScope in parallel, checking repository metadata and a small range from an actual weight file. An eight-second selection deadline bounds the comparison, and the fastest usable probe selects the initial source.

If a download fails, automatic mode can switch to the other available source. Matching content hashes allow interrupted data to be resumed across sources. Files with different content identities use separate partial downloads, and completed downloads undergo checksum verification. The model card displays the selected source and any switch during recovery.

Users can also select Hugging Face or ModelScope explicitly. Saved manual selections continue to select the chosen source, including after an upgrade.

## Start creating with the base model

First-time setup prepares the Qwen image-generation base model, including when an older preference has enhancement enabled. Once the environment and base model are ready, **Start creating** opens the workspace.

The workspace's right sidebar offers separate downloads for the text-to-image and image-editing enhancement models. Both download actions are available while enhancement is off. Users can prepare the model needed for a particular workflow and enable enhancement when its files are ready.

With enhancement off, ordinary image generation and reference-image import are available during an optional model download. The active download can be stopped independently of generation or its environment preflight.

## Estimated remaining transfer time

Model cards in setup and the workspace show an approximate remaining transfer time based on recent smoothed download speed. The estimate accounts for reusable downloaded data and adapts as the transfer rate changes.

The interface shows an estimation state while it gathers speed samples. Checksum verification has its own status, and the transfer estimate clears during verification and after completion, failure, or cancellation.

## Validation and upgrade

Validation on the AMD Windows development machine completed with the following results.

- All four C# projects compiled with zero warnings and zero errors.
- Python ran 151 tests, with 142 passing and nine opt-in hardware/model checks skipped. Download tests covered parallel source selection, hash-based resumption, recent-speed estimates, cached range accounting, cancellation, and process exit with real slow HTTP responses.
- All 365 offscreen and native checks passed. These exercised automatic-source defaults, saved manual selections, base-only setup, independent optional downloads, generation preflight during an optional download, separate cancellation, and remaining-time text in Chinese and English. Cards, download guides, and small-window layouts were inspected.
- Real model-download cancellation and missing PE file recovery passed. Existing GGUF weights were reused and verified, and the missing prompt file was fetched from ModelScope. A separate public-source probe fetched a 64 KiB range from an actual model weight.
- One actual AMD 512×512 text-to-image task completed all eight steps and produced a PNG in about 41 seconds through the app's generation flow.

Native checks used an isolated copy of the existing Python runtime with its installed dependency set. The run reused complete model weights. RTX validation for this release remains open. Existing AMD and RTX results retain their documented version and hardware scope. See [tested hardware](../testing.md) and [RTX hardware results](../rtx-4070-laptop-results.md).
