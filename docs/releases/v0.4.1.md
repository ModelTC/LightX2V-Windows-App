# v0.4.1 · Clean first use, pinned 0.6.1 and a clear launcher

With no saved user configuration the app opens the existing four-step assistant. Old development folders and legacy preference files no longer populate settings automatically. The workspace step offers an explicit import preview, applied only by Save and continue. Closing the preview discards it. Language-only preferences do not confirm a workspace or load/rewrite its history. Saved configured profiles still restore normally.

Hardware scanning stays automatic. Searching for Python environments, selecting models and preparing components are explicit user actions. The product does not contain machine-specific experimental paths or a special first-run testing mode.

Inference is pinned to official LightX2V 0.6.1, commit `43c6a11bb65b7357f06e9603fa92249bc16b484e`. Eleven common/Qwen Windows compatibility files are patched; five older H3-only patches are not carried forward. Both backend profiles share the verified source. Environment validation replaces an external source selection with a new managed version directory without modifying the external checkout. Python/dependency pins and resource-planning policy are unchanged. Reviewable patches, upstream ZIP SHA-256 and reproducible archive instructions are in the development documentation.

The ZIP's top level contains `LightX2V.exe`, `app`, and `docs`. The native launcher includes the app icon, forwards arguments and immediately exits after starting the WPF application. .NET and backend files stay inside `app`; no separately installed .NET is required. Layout-v2 manifests cover the public launcher and all payload files. Maintenance copies the verified complete layout and removes only listed files; unlisted user files remain. Legacy layout-v1 packages remain readable.

INT8, in-app updates and Stable promotion remain deferred. RTX and the complete display-scaling and generation acceptance matrix are still required before Stable. Local and AMD validation results are recorded separately from CI's compilation and package-integrity checks.

Validation for this batch: Windows Python regressions passed 170 tests with five opt-in checks skipped (171 existing cases plus four package-layout cases). The final self-contained WPF core suite passed 515 assertions, with five additional real-import checks passing in the native-Python run, including import cancellation, unconfirmed-workspace preservation, pinned-source selection, and layout-v2 selective uninstall. On Radeon 8060S, the actual app view model completed Standard 512 text-to-image, eight-reference Adaptive editing, and both T2I/I2I prompt-enhancement generation chains with the new source. These individual hardware samples do not complete the full Stable acceptance matrix.

The public launcher passed an independent native argument probe (Unicode/spaces, empty arguments, embedded quotes and trailing slashes). The packaged app entered first-run setup while legacy development directories remained present. A real packaged maintenance process waited for its parent, removed the layout-v2 fixture launcher/model, retained unlisted files and cleaned its helper copy.
